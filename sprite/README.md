# sprite/ — 素材画像

ここに置いた画像をゲームで使います。
**元の素材はそのまま置いておいてください。** ゲームが直接読むのは
`sprite/opt/` に生成された軽量版のほうです。

## 使い方

画像を足した・差し替えたら、これを実行します。

```sh
node tools/build-sprites.js
```

これが次の 4 つをまとめてやります。

1. **余白の切り詰め** — 不透明な部分の外接矩形まで切る
2. **向きの統一** — 自機は右向き、敵は左向きに揃える
3. **縮小** — ゲームで使う大きさまで落とす（最大 256×128）
4. **一覧の生成** — `sprite/opt/manifest.js` を書き出す

現在の素材での実績: **11.4MB → 1.19MB（89.6% 削減）**。

生成物（`sprite/opt/`）もリポジトリに入れてあります。
ビルド手順を踏まなくても `index.html` を開けば動くようにするためです。

## ファイル名の決まり

名前は自由ですが、次の 2 つだけ守ってください。

- 自機の絵はファイル名に `player`、敵の絵には `enemy` を含める
- 連番（`_001_` のような数字）を入れる。これが画像の ID になります

現在の素材だと `side_player_001_transparent.png` → ID `p001`、
`side_enemy_020_transparent.png` → ID `e020` になります。

この ID を、`js/config.js`（自機）と `js/enemies.js`（敵）で
どの機体・どの敵に割り当てるか指定しています。

## 向きの自動判定について

機体は普通「先端が細く、後部が太い」ので、
左右の端 15% の平均の高さを比べて機首の側を判定しています。

ただし **エンジンの炎が後ろに伸びていると、後部のほうが細く見えて
判定を間違えます**。現在の素材では 40 枚中 13 枚がこれに当たりました。
間違えたものは `tools/build-sprites.js` の `FLIP_OVERRIDE` に
番号を書いて手で直しています。

新しい素材を足したら `docs/sheet-enemy-*.png`（自動生成される一覧表）を見て、
向きがそろっていない番号を `FLIP_OVERRIDE` に足してください。

## 確認用

```sh
node tools/bestiary.js     # docs/bestiary.png に敵を全種類並べる
```

戦闘中の画面では「見分けがつくか」が判断できないので、
絵の大きさや縁取りの調整はこの一覧を見ながら行います。

## 弾に画像は使いません

弾は数が多く、**丸＝敵弾 / 菱形＝追尾弾 / 四角＝アイテム**と
形で区別しています。ここを画像にすると見分けがつかなくなります。

## 暗い素材について

素材はそのまま貼ると暗い機体色が黒い背景に溶けるので、
描画時に**種類ごとの色でシルエットの縁取り**を焼き込んでいます。
「色＝敵の種類」という手がかりを残しつつ、元の絵も活かすためです。
